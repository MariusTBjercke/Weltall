Tests that abort with 0xC0000409 on a machine that has only the USA discs.

Why: each of these reaches `REQUIRE_DISC(...)` with a release whose disc is *optional* — the English
undub, a fan translation, or Perfect Works Build. `REQUIRE_DISC` handles a missing disc with Catch2's
`SKIP`, and this project compiles with exceptions off (`/EHs-c-`, `-fno-exceptions`). Catch2 then
prints `SKIPPED: disc not found in Games/` and terminates the process deliberately:

    Catch will terminate because it needed to throw an exception.
    The message was: Explicitly skipping tests during runtime requires exceptions

So these are not failures of the code under test, and `ctest` exits 1 on such a machine by design.
A failure that is NOT in this list, or one whose message is not that `SKIP`, is a real regression.

Snapshot: 19 tests, Weltall 1.0.1, 2026-11-07, `Games/` holding only `Xenogears (USA) (Disc 1).bin` and
`(Disc 2).bin`. Re-derive with `ctest --preset windows 2>&1 | Select-String "tests FAILED" -Context 0,25`.
The names can change when upstream edits a test; the criterion above is what matters.
